## 결과물 (코드 기준 사실)

동작하는 것:

- **시크릿 URL** `/r/[token]` 신청·재제출(full replace), 토큰은 middleware로 검증
- **구글 폼** → Apps Script → `/api/google-form-submit` → 동일 RPC 경로 (`skipOpenCheck`)
- **일괄 배정** Admin **Run full assignment** — MCMF, mon → tue → thu
- **대기열** eliminated, Cancel 시 `promoteOnCancel` 승격
- **공개 현황** `/status`, 본인 조회 `/r/[token]/check`
- **Admin:** Secret URL 발급/마감, Search Delete(배정 전), Grid Cancel, Export Excel(요일·waitlist·연맹 요약), Reset cycle(`archive_and_reset_cycle`), How to use
- **검증·유지보수 스크립트:** `verify:assignment`, inject/clear, backfill, recover 등
- **감사 로그:** delete / cancel / resubmit

### 유지보수 스크립트가 생긴 맥락 (git·파일 헤더)

`scripts/maintenance/`·`scripts/dev/`의 backfill / recover / reconcile / purge / inject / clear는 **2026-05-22 전후**에 집중적으로 추가·갱신됐다 (`fd69f32`, `83b5f92`, `c9b4a69` 등 — 커밋 메시지는 `.`이 많음). 같은 시기 `recover-waitlist`는 특정 테스터 이름 필터(`테스터_52` 등)로 돌릴 수 있게 되어 있고, `backfill-empty-slots`는 「대기열에서 빈 슬롯 채우기」를 Admin 버튼 밖에서 재실행하는 CLI다. 이후에도 `7c115c1` Dedupe eliminated waitlist 등 **배정·대기열 정합성** 커밋이 이어진다.  
즉 초기에 즉시배정/Hopcroft·빈자리+대기자 문제가 반복될 때, **일괄 배정만으로 안 끝나는 빈 슬롯·대기열·고아 players를 로컬에서 수동 복구·재현**하려고 스크립트 세트가 쌓인 것으로 보는 것이 커밋 시점·스크립트 역할과 맞다.

## 개선 방향

기존 버그·갭 수정:

1. 제출 경로에서 `last_assignment_run` + 정책에 맞게 잠금 강제하거나, 안 쓸 거면 `ASSIGNMENT_LOCKED_MESSAGE` 제거.
2. RPC preferred_blocks 파싱을 안전한 캐스트·앱 단 메시지로 감싸기.
3. `day_of_week IN ('mon','tue','thu')` CHECK 추가.
4. 배포 Apps Script와 `onFormSubmit.gs`·문서를 한 소스로 맞추는 절차(버전/체크리스트).
5. (선택) Apps Script에서 구글 폼 `setAcceptingResponses(false)`를 Admin「마감」과 연동 — **제안** (미구현, 기술적으로 가능).

새로운 방향 (**제안** — 코드에 지표/알림 구현 없음):

6. **제안:** 배정 실행마다 성공률·대기자 비율(assigned / eliminated / 빈 슬롯 수)을 `settings` 또는 별도 테이블·로그에 남겨, 사이클 간 비교·이상치 모니터링.
7. **제안:** `audit_log`를 Admin UI에서 조회하거나, delete/cancel/resubmit 시 슬랙·메일 등 알림에 연결해 운영 사고 추적을 스크립트/DB 콘솔 밖으로 끌어내기.

정리용:

8. `scripts/maintenance/run-batch-assignment.ts` 로그의 `"Hopcroft-Karp"` 문구를 MCMF에 맞게 수정 (동작은 이미 MCMF, 문구만 잔존).
